# Rapid Learning — 快速学习系统

> 一套独属于你的、流程化的快速学习 Skill。两阶段递进，三种角色自动切换，帮你把"学新东西"这件事变成可重复的标准化流程。

---

## 这是什么

一个安装在 WorkBuddy 中的用户级 Skill，专门用于**学习编程技术、计算机基础和 AI/ML 工程化知识**。当你表达学习意图时（如"学一下 Redis""了解一下 Docker"），它会自动触发，按照一套精心设计的两阶段流程带你学习。

**核心理念**：学习不是一次性的"看完 = 学会"，而是分阶段的——先快速建立知识骨架（知道全貌），再按需深入（动手掌握）。不是每个技术都需要学到底层原理，切换由你的实际需求触发。

---

## 设计哲学

| 问题 | 解法 |
|------|------|
| 学新东西时不知道从哪入手 | Phase 1 自动生成知识树，标好重点和延后项 |
| 专业文档看不懂、容易劝退 | 生成"人话版"HTML 文档，用比喻和最小代码示例讲清楚 |
| 不知道学到什么程度算够 | 阶段隔离建议明确划分"看懂即可"和"必须会写" |
| 看完就忘、没有产出 | Phase 2 按目标产出具体交付物（考点树/项目代码/原理文档） |
| 被动学习容易走神 | 教练模式出任务、追问、评判，逼你主动思考 |
| 卡住了不好意思问 | 同一概念卡住 1 次自动降级为助手模式，重新用人话解释 |

## 两阶段学习流程

### Phase 1：知识骨架（自顶向下）

**目标**：在最短时间内建立心理地图——这个技术是什么、有哪些核心模块、重点在哪、哪些可以延后。

**不算学会**，仅视为"建立了知识索引"。

**触发条件**：你表达学习意图 + 知识属于编程/计算机基础/AI 工程化。

**角色**：🧭 Navigation（导航模式）

**每次必出三件套**：

| 产出 | 格式 | 说明 |
|------|------|------|
| 知识树 | Markdown 列表 | 4-6 个主干模块，每主干最多 4 个子节点。⭐ 标重点，🔒 标延后 |
| 人话文档 | HTML 文件 | CSS 排版的网页，直白中文 + 比喻类比 + 最小可用代码示例 |
| 隔离建议 | 表格 | 明确划分每个内容是"看懂即可""必须会写"还是"延后" |

输出完成后自动切入等待状态。

---

### 等待状态（助手待命）

Phase 1 输出完成后进入等待。你可以：
- **提问** → 进入 🤝 Assistant 模式，用人话解释概念，不主动推进节奏
- **发起 Phase 2** → 进入 🎯 Coach 模式，开始深度学习

---

### Phase 2：深度掌握（自底向上）

**目标**：从具体任务出发反向深入，达到"能动手做出来"和"能讲清楚为什么"。

**算学会**，按具体目标动态定义验收标准。

**角色**：🎯 Coach（教练模式）

**四种目标，各自不同的产出和验收标准**：

#### 目标一：面试准备

| 产出 | 说明 |
|------|------|
| 考点树 | 从知识树扩展，标注面试频率（🔴高频/🟡中频/🟢低频） |
| 15 道常考题型 | 含题目、考察点、参考答案要点、常见错误 |
| 模拟面试 | 逐题提问 → 你回答 → AI 评判打分（1-10）→ 指出遗漏 |
| 自检清单 | 对照检查是否覆盖所有考点 |

**验收**：能通过模拟面试问答，关键要点覆盖到位，手写代码题能独立完成。

#### 目标二：项目 / Demo

| 产出 | 说明 |
|------|------|
| 项目规划文件 | 项目目标、技术选型、预期成果、目录结构 |
| 分阶段任务列表 | 每个任务含目标、材料、期望产出、自检标准 |
| 带注释代码 | 教练引导你编写，关键难点可给参考实现 |
| 任务状态跟踪 | 自动同步任务完成状态 |

**验收**：能独立完成所有任务，并清楚解释每个设计决策。

#### 目标三：系统掌握

| 产出 | 说明 |
|------|------|
| 完整三层知识树 | 在 Phase 1 基础上扩展到三层，补全子节点 |
| 深度原理文档 | 核心机制推导、设计权衡、横向对比分析 |
| 关联分析 | 模块间依赖关系、数据流向、影响范围 |

**验收**：能画出完整三层知识树，讲清核心机制之间的关联与设计权衡。

#### 目标四：自定义

进入前与 AI 协商一个可验证的结果描述，以此作为验收标准。

## 三种角色自动切换

```
Phase 1 新概念 ──▶ 🧭 Navigation（导航）
                       │
                       ▼ 输出完成后
                 等待状态 ──▶ 🤝 Assistant（助手）← 用户提问时
                       │
                       ▼ 用户发起深度学习
                 🎯 Coach（教练）
                       │
                       ▼ 用户卡住 >1 次
                 🤝 Assistant（强制降级）
                       │
                       ▼ 确认理解后
                 🎯 Coach（切回继续）
```

| 角色 | 触发场景 | 行为 | 不做什么 |
|------|----------|------|----------|
| 🧭 Navigation | Phase 1 新学技术 | 主动输出知识树和文档，告诉先看什么后看什么 | 不深入细节、不出练习题 |
| 🤝 Assistant | 等待中用户提问 | 用比喻和人话重构概念，翻译专业文档 | 不主动推进节奏、不出任务 |
| 🎯 Coach | Phase 2 深度任务 | 出任务、追问理解、评判答案、验收成果 | 不直接喂答案（项目模式用户要求除外） |

**自动降级规则**：你对同一概念卡住超过 1 次（表示困惑、要求重复解释、回答错误）→ 强制切回 Assistant 模式，用人话重新解释，确认理解后再切回 Coach。

## 知识范围

| 类型 | 占比 | AI 行为 |
|------|------|---------|
| 编程技术 | 70% | 准备可执行代码、项目结构模板、环境搭建指令、常见报错方案 |
| 计算机基础 | 20% | 图解 + 类比 + 实验模拟，层次化图解和概念问答 |
| AI/ML 工程化 | 10% | 侧重"怎么用"，直觉解释 + API 调用示例，不做数学推导 |
| 通识/其他 | 0% | 不启用此 Skill，回退为普通对话 |

## 如何使用

### 触发方式

在日常对话中直接表达学习意图，Skill 会自动识别并触发：

```
你：学一下 Redis
→ 自动进入 Phase 1，输出知识树 + 人话文档 + 隔离建议

你：Redis 的持久化机制没太看懂
→ Assistant 模式，用人话重新解释

你：我准备面试，Redis 要考
→ 进入 Phase 2 Coach 模式，出考点树和模拟面试题

你：用 Redis 做一个排行榜系统
→ 进入 Phase 2 Coach 模式，出项目规划和任务列表
```

### 不触发的情况

- 学习非技术类知识（如历史、烹饪、语言学习）
- 纯粹的技术问题咨询（如"Redis 怎么设置过期时间"——这是提问，不是学习）

## 文件结构

```
rapid-learning/
├── SKILL.md                              # 核心规则：两阶段流程、角色切换、知识范围
├── README.md                             # 你正在看的这个文件
├── references/
│   ├── phase1-output-spec.md             # Phase 1 三种产出的详细格式规范
│   └── phase2-output-spec.md             # Phase 2 四种目标的产出规范
└── assets/
    └── knowledge-doc-template.html       # 人话文档的 HTML 模板（自适应深浅色主题）
```

### 各文件职责

- **SKILL.md**：Skill 的入口文件。WorkBuddy 加载 Skill 时首先读取此文件，包含完整的流程定义、角色切换规则和决策树。是 AI 执行学习流程时的"操作手册"。
- **references/phase1-output-spec.md**：Phase 1 输出的详细格式模板。包含知识树的 Markdown 格式规范、HTML 人话文档的结构要求、隔离建议表格的字段定义。
- **references/phase2-output-spec.md**：Phase 2 四种目标（面试/项目/系统掌握/自定义）各自的产出格式和验收标准。AI 在进入 Phase 2 时按目标加载对应规范。
- **assets/knowledge-doc-template.html**：HTML 文档模板，包含 CSS 样式（支持浅色/深色主题自动切换）、概念卡片、比喻区块、代码块、学习路径、常见误区等组件。AI 生成人话文档时基于此模板填充内容。

## 设计决策记录

### 为什么是两阶段而不是一步到位

学新东西时最大的坑是"一上来就钻细节"。Phase 1 强制你先看全貌——4-6 个主干、每主干最多 4 个子节点，宁精勿多。有了心理地图之后，Phase 2 的深入才有方向感。

### 为什么 Phase 1 不算"学会"

看懂架构 ≠ 会用。Phase 1 交付的是"知识索引"——你知道有什么、重点在哪，但不具备独立动手能力。只有 Phase 2 按目标验收通过才算学会。

### 为什么教练模式不直接喂答案

主动回忆比被动阅读的记忆效果好得多。教练模式让你先尝试，再评判，逼迫你主动思考。但如果你明确要求"直接给参考代码"，也会提供——附上详细注释和原理解释。

### 为什么有自动降级机制

教练模式如果在你卡住时继续追问，只会增加挫败感。卡住 1 次就切回助手模式重新解释，确认你理解后再继续——在"逼你思考"和"不让你崩溃"之间找平衡。

## 迭代计划

这套 Skill 是活的，用几次之后可能会发现需要调整的地方：

- [ ] 知识树的模块数量限制（4-6）是否合适
- [ ] 教练模式"不喂答案"的力度是否需要调节
- [ ] HTML 文档的排版风格是否需要微调
- [ ] Phase 2 的目标类型是否需要扩展

使用中遇到任何不顺手的地方，直接告诉 WorkBuddy "帮我改一下 rapid-learning skill"，即可迭代更新。
